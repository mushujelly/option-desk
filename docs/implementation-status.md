# Option Desk 开发进度与交接记录

更新时间：2026-09-26 09:14（Asia/Shanghai）。本文件描述当前实现与验证结果；[基础设施设计 v0.9](infrastructure-design.md) 仍为设计依据。首版已能独立运行，但数据补全和全部设计能力尚未验收完成。

## 一、当前结论

来源读取、合约解析、去重、分钟基准构建、当前行情采集、查询接口与监控页面已形成真实数据链路。项目拥有自己的配置、数据库、运行环境、请求预算与任务队列，不依赖 midas 的运行进程或文件；midas 仅作为实现参考。OpenD 是独立外部行情网关，仍需运行并登录。

用户已授权 Discord 与 MongoDB 来源的只读获取和本项目内存储；随后授权按 midas 清单补齐来源。已配置 20 个频道及 MongoDB 对应频道范围，不向这些来源写入。

## 三、已实现功能

### 独立运行与持久化

- Python / FastAPI、React / TypeScript、本项目 PostgreSQL；本地启动脚本同时管理数据库、API 与采集进程。
- `.env` 仅使用 `OD_` 配置；凭据不写入文档，数据保存在本项目数据库。
- 原始消息、逻辑事件、合约、来源观察、冻结基准、共享当前行情、关注列表、任务及请求预算分别存储。
- 演示数据与正式采集库分离，人工样例明确标注 DEMO。

### 来源采集与解析

- 20 个 Discord 频道及 MongoDB 对应消息只读采集。清单在项目内保存副本。
- Discord 实时游标与向前历史回填游标分离；回填记录时间范围、页数、消息数及失败状态，重启续跑。
- MongoDB 使用时间与文档 ID 分页；频道范围变更使用不同游标，积压期间继续翻页。
- 已支持结构化合约、OCC 代码、明确 ISO 日期合约、UW 提醒卡片、Cheddar Flow 字段卡片及带完整年份的紧凑合约格式。
- 无法可靠解析的消息保留原文与诊断；新闻、股票成交、缺少年份、截断文本与仅图片内容不强行转换为期权事件。
- 原始事件时间超出回填窗口的旧消息重发，保留诊断，不作为窗口内新事件。

### 去重与事件时间

- 单条 UW 提醒里的多个相同合约链接识别为同一提醒。
- 同频道、同 webhook、同原始 embed 精确时间、同完整提醒内容的 UW 转发共用逻辑事件；缺失证据或原始时间/内容不同的消息不按合约简单合并。
- Cheddar 提醒使用来源明确时间与内容形成转发身份；识别出的原帖引用可用于已有跨来源身份规则。
- 来源修订与旧身份升级保留原始记录和冻结包；旧关联标记失效或 superseded，不覆盖旧价格。
- UW 原始卡片时间是提醒时间，不等于已证实的单笔成交时间。区间均价和区间成交量不冒充单笔成交价或手数。

### 两份状态与行情任务

- 每个逻辑事件与合约保留一份冻结基准；当前行情按合约共享并覆盖更新，查询不新增快照。
- 来源值优先；缺失价格按对应一分钟 K 线收盘价估算。盘中不拿相邻分钟替代，非交易时段只查最近已结束交易日。
- 非交易时段找不到有效分钟数据时退出监控并保留诊断；无手工重抓基准入口。
- 当前行情采用同一提供方的数据包，记录字段来源、时间、缺失原因及可比性。
- OpenD 当前快照最多 20 个合约批量获取，逐合约验证身份、经任务租约提交；失败批次后按单合约重试。
- 已到期合约退出当前行情轮询；连续失败的批量行情路径进入冷却，避免堵住其他合约。
- 当前行情与基准任务交替调度；预算在数据库中共享执行，限流等待不耗尽业务重试次数。
- 分钟历史按合约/交易日使用有界内存缓存，逐事件仍筛选精确分钟；缓存不作为持久化行情历史。

### 页面与接口

- 合约监控、详情对照、来源流水、关注列表、数据源与任务页面已可使用。
- 合约列表按事件时间排序；监控与关注列表按纽约日期隐藏已到期合约，历史原文与基准保留。
- 基准未完成时先展示已有来源字段，并标明待分钟校验；当前行情分别显示等待、失败或到期状态。
- 逐频道显示历史回填进度。SSE 通知触发重新读取接口，辅以定期同步。
- 单个基准对照接口原子读取冻结基准与当前版本；来源流水支持游标分页。

## 五、未完成与已知限制

1. **补全未结束**：剩余 5 个未到期合约尚无当前行情包，1,219 条未到期提醒基准待处理。须继续区分排队、限流、无权限、无历史数据与解析问题，不能承诺每个字段最终都有值。
2. **长时间运行未验收**：本次曾发生服务停止，原因未确认；缺少已验收的常驻托管、异常自动拉起、完整熔断与恢复演练。
3. **完整来源格式未覆盖**：缺少年份的到期日确认、图片内容、复杂多腿、调整合约和更多自由文本仍有缺口；来源历史修订扫描未启用。
4. **历史估值模型未启用**：IV / Greeks 模型估算与其误差验证、基本面背景等设计能力尚未完成。
5. **提供方验证不齐**：Schwab / Polygon 适配器已有代码，但当前环境未做真实接入验收；本实现的 Schwab 分钟历史回查不支持。OpenD 实时权益未确认，保守显示延迟。
6. **列表与导出范围有限**：基准列表默认返回 200 条、最多 500 条；导出最多 500 条。当前页面加载数不能当作数据库总量，基准列表完整分页待补。
7. **部署与运维待验收**：Docker 配置尚未运行验证，数据库备份恢复、规模与性能验收未完成；数据库外键/正式迁移机制仍需按设计核查完善。
8. **到期判定粒度**：当前使用纽约日期比较到期日，尚未按合约具体交易截止时刻细分当日盘后状态。

## 七、运行与交接

在项目目录执行 `npm run dev`；本地页面为 http://127.0.0.1:8765 。独立启动和环境配置见 [README](../README.md)。不要重复启动占用同一端口的服务，也不要清空数据库或游标来重跑历史。

- 正式数据使用项目 `.env` 指定的独立数据库；不要在文档或日志输出凭据。
- 数据库端口 55432，API 端口 8765，OpenD 默认端口 11111。
- 回填窗口默认 30 天；已建立的回填任务使用其保存的固定边界，修改配置不会自动重置任务。
- 查进度需区分来源读取、提醒解析、基准处理、独立合约当前行情四个口径；汇报页面相关进度时排除已到期合约。
- 本文件中的统计是定时点事实。后续更新请整体修订对应表格，避免追加互相矛盾的旧状态。

## 收盘后字段补充（2026-09-26 新增）

用户授权截图中的缺失字段使用事件当日收盘后数据替代。已实现单次冻结补充包、来源优先、交易日与收盘窗口校验、当前行情更新后自动补充，以及页面逐字段“当日收盘后（替代值）”说明。原基准不改写；补充属于同一逻辑基准，不形成每日快照。历史日期的专用收盘后数据尚未接入，不能用今天快照补过去日期。OI 有效日期未知仍保留未知，历史模型估值仍关闭。

本次已从现有符合日期和收盘窗口的当前包补入 64 条提醒的收盘后参考；55 项测试通过，前端构建通过，服务已重启加载。该数字只表示有补充包，不表示每个字段均可得。
