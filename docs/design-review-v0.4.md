## P1：IV/Greeks 模型估算需要验证门禁

第 14.2 节允许在来源缺失时，用期权分钟 close、标的同分钟价、剩余期限、利率/股息假设及适用模型估算 IV/Greeks。风险点：

1. 美股期权多为美式，直接套用 Black-Scholes 会产生系统性误差（尤其是实值 put 的提前行权溢价）；
2. 股息假设（离散股息 vs 连续收益率）与利率来源（SOFR？国债？）尚未确定；
3. 深度虚值期权 vega 接近零，IV 数值求解可能失败或不稳定。

建议：阶段 0 增加模型验证门禁——用历史样本对比模型 IV 与交易所公布的 IV，误差分布可接受才启用该能力；否则 v1 默认只展示来源值，模型估算延后到后续阶段。

## P1：分钟 close 的时效性

流动性差的期权，某分钟的 close 可能是数小时前最后一笔成交的价格，用它估算 IV/Greeks 会产生误导性结果。

建议：若 K 线提供分钟内最后成交时间，一并保存；close 对应成交距事件时间过久的，估算结果降置信度或直接标不可用。具体阈值在阶段 0 接入核验时确定。

## P1：非交易时段事件的分钟映射规则

第 14.2 节要求“确认合约身份及事件时间能映射到明确的交易分钟”，但来源消息经常出现在盘后/隔夜（如晚间转发下午的单子），或根本缺少可解析的事件时间。

建议写死规则：能解析出交易时段内的事件时间 → 使用该分钟；否则基准价格字段直接 `unavailable`，不向前/后寻找有数据的分钟（与“不静默挪到相邻有成交的分钟”一致）。

## P2：无成交分钟的行为写死

第 20 节第 11 项把“无成交分钟行为”列为待核验。建议直接与“不静默挪到相邻有成交的分钟”绑定为设计决策：无成交分钟 = 该字段 `insufficient_data`，不允许实现层自行向前/后找分钟。

## P2：可比性矩阵建议写成小表

第 10.2 节目前是文字描述：“来源值/分钟估值/模型值与当前值的差异只能标为‘估算变化’，不得称精确收益；方法不兼容时差值为空”。实现时容易分歧，例如 `model_estimate` 的 IV 与当前交易所 IV 之间算“估算变化”还是“不兼容”。

建议把 `value_origin` 两两组合的可比性写成一张小表（可比 / 估算变化 / 不兼容），供对照接口与前端直接引用。

## P2：联调期的 midas 并存风险

运行约定明确“Option Desk 正式运行时用户会停掉 midas”，但阶段 1–2 联调时两项目大概率并行，Schwab token 刷新冲突会在那时先出现。

建议加一句话：联调期手动错峰使用，或明确接受该风险并记录。

## P3：“长期挤占”需要量化

第 13.2 节：“空闲份额可借用，但不能长期挤占实时任务”。建议把“长期”量化（如连续借用上限 X 分钟或 Y 个调度周期），否则调度器实现时无法编写借用上限逻辑。

## 仍然悬置的早期建议

- 附录 DDL 草稿（按 `event_baselines` / `current_states` / `context_cache` 新表写）。
- 来源事件列表的 keyset / cursor 分页（“稳定分页”目前仍是文字要求）。
- 可观测性 SLI 与告警阈值（采集延迟 p95、断源判定时间、字段覆盖率）。
- 交易所日历点名具体库（不手写夏令时/半日市逻辑）。
- 原始报文归档目录命名规范与读取时 hash 校验。
- 请求预算已在第 13.2 节完整覆盖，不再重复。
